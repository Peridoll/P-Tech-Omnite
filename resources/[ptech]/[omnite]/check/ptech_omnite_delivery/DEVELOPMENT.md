# Omnite Delivery 開発記録

## 2026-11-27 配達先NPCの表示方法を選択

工具箱の配達先NPC配置・編集フォームへ「常時見せる／受注時のみ見せる」を追加。`visibility='always'/'mission'` として配置DBとConfig書き出しへ保存し、サーバーでも値を検証する。未指定の既存配置は今までどおり受注時のみ。

常時表示は近距離にいる各プレイヤーへ表示するが、箱の取得権限は受注中の該当地点に限定。表示方法の変更は配信後のNPC確認で反映し、店舗受付の表示は変更しない。

構文・モック試験で表示方法の保存・検証・切替、Config往復、未受注での常時表示、箱の無断取得不可、旧配置の既定値を確認。既存の配達・会計・演出試験も通過。FiveM実機未検証。

## 2026-11-27 配達先NPCを受注時だけ表示

`main/client.lua` で配達先NPCの表示条件を、本人の受注中・未集荷・選択済み地点・期限内に限定。NPCは従来どおり非ネットワーク生成なので、受注していない他プレイヤーには見えません。店舗NPCの近距離表示は維持します。

箱の受取、取消、納品完了、JOB変更などによる配達終了、ログアウト時に該当NPCとターゲットを除去。生成待ち・モデル読込中に条件が変わった場合も生成を中止します。消失後の再生成も表示条件を満たす配達先だけが対象です。

構文・モック試験で未受注時に配達先が生成されないこと、受注後に選択した地点だけ生成されること、未選択地点の非表示、集荷直後の削除、生成待ち中の取消を確認。既存の配達・会計・演出試験も通過。FiveM実機未検証。

## 2026-11-27 NPC未生成の直接原因をログで確認

実クライアントのCitizenFXログとユーザーのF8画像で、`main/gameplay.lua:61` と `main/client.lua:193` の `attempt to index a nil value (global 'os')` を確認。受注によりmissionが有効になると、NPCストリーミングループと運搬・案内ループが `os.time()` で停止していた。ブリップは受注時に別処理で作成されるため、ブリップだけ残り遠方の配達先NPCが作成されない。

- `main/client.lua` / `main/gameplay.lua`：クライアントの期限・残り時間判定を `GetCloudTimeAsInt()` へ変更。サーバー側の `os.time()` は維持。
- 画像に併記された `QBCore:Client:OnJobUpdate was not safe for net` も修正。プレイヤー読込・JOB更新・ログアウトの3イベントを `RegisterNetEvent` で登録し、サーバー起点の通知を受け取る。
- `dev/client_spec.lua` / `dev/gameplay_spec.lua`：`os=nil` を明示して実クライアントと同じ制約で試験。受注中のNPC生成ループ継続、運搬、案内、期限切れの試験が通過。既存の会計・配達試験も通過。
- 前回の消失後再生成対策だけでは、このループ停止は解決していなかった。修正後のFiveM実機は未検証。更新・再起動後に受注し、配達先へ移動してNPCとF8エラーの解消を確認する。

## 2026-11-27 ブリップがあるのにNPCがいない場合

配達先NPCが消えた原因自体は実機ログがなく未確定。ただし、生成済みキャッシュに存在しないエンティティが残ると再生成されず、生成処理の例外でもloading状態が残る不具合をコードで確認した。

- `main/client.lua`：生成前に地点ごとのloading状態を確保し、多重生成を防ぐ。ミッションエンティティとして保持する。近距離で実体がなくなったらキャッシュを解除して再生成する。
- 生成全体を例外処理し、失敗時は途中のNPCとターゲットを掃除して次の確認で再試行する。ターゲットの削除に失敗しても実体の掃除を継続する。F8には地点名・ID・モデル・座標・原因を出す。同じ失敗の連続ログは抑制する。
- 消失NPCの再生成と、ターゲット登録失敗後にloadingが残らず再試行するモック試験が通過。既存の配達・会計・演出試験も通過。FiveM実機未検証。

## 2026-11-27 NPCの足元配置・店長の報酬設定

- `main/client.lua`：画像付き実機報告でモデル最小Zの減算による埋没を確認したため、その補正を撤回。生成後にSetEntityCoordsNoOffsetで保存したプレイヤー中心座標へ直接配置する。地面の検索で別階の床へ移動させない。旧NPCも生成時に補正するためDBの一括変更や再登録は不要。

- 構文・モック試験：NPCの生成高さ、通常店員に報酬設定を表示しないこと、店長設定の送信と権限検証、管理者の配置編集で店長設定を上書きしないこと、受注済み報酬を変更しないことを確認。既存の配達・会計・演出試験も通過。

## 実装状態（2026-11-26）

対象は `ptech_omnite_delivery`。本チャットの確定項目と現行の店舗別会計仕様を照合し、本実装とモック試験を完了しています。FiveM実機・実DBは未検証です。

| 確定項目 | 本実装 |
|---|---|
| ツールボックスから管理 | adminと工具箱を検証してデリバリー管理を開く |
| 店舗・配達先NPC | 個別モデル、現在地と向き、編集・削除、DB保存、Config書き出し |
| 店員限定の受注 | 店舗JOBが一致する店員のみ。勤務外も利用可能 |
| 全店舗共通の配達先 | 同じrouting bucketの配達先NPCからランダム選択 |
| 配達の進行 | 箱ブリップで集荷先を案内し、箱受取後は受注店舗への経路へ切り替え |
| 配達の演出 | キャンセル可能な受け渡し、徒歩での箱持ち、乗降時の表示切替、残り時間案内 |
| 報酬・獲得ポイント | 初期40万円・200pt。受注時の値を保持。店長は今後の報酬額を変更可能 |
| 店舗別ポイント・金庫 | 同じJOBでも店舗NPCのIDごとに独立。金庫操作は店長のみ |
| 報酬の確保と返金 | 受注時に確保。不足時は受注不可。取消・期限・JOB変更・切断で返金 |
| 素材交換 | 普通・タバコ葉・紅茶葉は3pt、高級・甘味は5pt。管理者が編集可能 |
| 通常ショップ | toolboxのショップ管理が担当。Delivery内の旧market配置は稼働対象外 |
| 再起動・精算 | 未完了の確保金は一度だけ返金。成否不明の支払いはadminの精算確認へ隔離 |

通常ショップの商品・在庫・販売権限・金庫設定は `ptech_omnite_toolbox` で管理します。素材の現金価格は普通・タバコ葉・紅茶葉が7,500、高級・甘味が12,500です。Deliveryの`products[].cash`は従来データとの互換用で、Deliveryから現金ショップを開く機能はありません。

## 試験

リポジトリのルートから実行します。Node.jsと既存のluaparse/fengari依存を使用します。

```powershell
node 'resources/[ptech]/[omnite]/ptech_omnite_delivery/dev/run.cjs'
node 'resources/[ptech]/[omnite]/ptech_omnite_delivery/dev/gameplay.cjs'
```

2026-11-26に上記の試験は通過しました。確認範囲は次のとおりです。

- Lua構文、カタログ追加・編集・削除・再読込、古い編集の拒否。
- 店員限定、勤務外受注、店舗別残高、店長限定金庫、受注時の報酬固定、二重納品拒否。
- 確保金・返金・ポイント確定の重複防止、再起動回復、不明な送金の隔離。
- 返金中の別操作を拒否し、一時的DB障害の次回確認で再試行すること。
- 現金支払い後のDB確定失敗を再試行しても現金とポイントを二重加算しないこと。
- 個別NPCモデルのConfig往復、配達先フォームに店舗設定が混じらないこと。
- 演出キャンセル、モデル読込中の中断、乗降・死亡・拘束・所持箱の変化、案内表示の後始末。

temporary refund/settlement DB failureは障害を意図的に発生させた試験のログです。実DBのSQL実行や実際のox_inventory連携を確認したことは意味しません。
