# Omnite Delivery

工具箱 → デリバリー管理で、店舗NPCと全店舗共通の配達先NPCを登録します。一般ショップの設置・商品・在庫・売上管理は ptech_omnite_toolbox 内で扱います。

## 利用・管理

- 配達を受注できるのは、その店舗NPCに設定したJOBの店員です。勤務外でも利用できます。
- 配達先NPCをランダムに1人選び、箱ブリップと経路を表示します。同じ街（routing bucket）の全配達先が対象です。
- 工具箱 → デリバリー管理 → 配達先NPCの配置・編集 →「NPCの表示」で「常時見せる／受注時のみ見せる」を選択できます。「受注時のみ」は受注中の本人に選択地点だけを表示し、箱の受取・取消・期限切れ・ログアウトで消します。「常時」は近くにいる全員へ表示しますが、箱を受け取れるのはその地点を指定された受注者だけです。店舗の受付NPCは常時の近距離表示を維持します。
- 配達先で箱を受け取り、受注した店舗へ納品します。納品報酬とポイントは受注時点の設定値を使用します。
- 店舗NPCごとにポイントと金庫を管理します。別店舗のポイントは共有しません。
- 金庫は該当JOBのisbossのみ入出金可能。店舗NPCの「配達員の報酬設定（店長）」から1回分の金額を設定します。変更は次の受注から適用し、受注済みの報酬は変えません。
- 管理者は工具箱からNPC配置・移動・削除、個別NPCモデル、JOB、獲得ポイント、素材の交換ポイントを編集できます。配達報酬は店長の専用設定に分け、NPC配置編集で上書きしません。
- 店舗NPCの初期値は報酬400,000、獲得200pt。低級素材3pt、高級素材5ptです。既に個別設定済みのNPC・交換率は保存値を優先します。
- ポイント交換は金庫残高にかかわらず利用できます。

## 金庫と障害復旧

受注時に金庫から報酬を確保し、不足していれば受注を拒否します。キャンセル・期限切れ・JOB変更・ログアウトは確保分を返金します。
進行中の確保金をDBへ記録するため、サーバーやリソースの再起動後にも未完了分を一度だけ返金します。

現金移動とDBは共通のトランザクションを持ちません。支給・入出金の途中でサーバーが落ちた場合、移動済みか不明な取引は自動で再支給せず「障害時の精算確認」に残します。adminがログ・実残高を確認して確定します。
通常の未完了配達は自動返金されます。DB復旧が遅れた場合も報酬を二重に支給しません。

## 保存

- ptech_omnite_delivery_locations：NPC配置
- ptech_omnite_delivery_catalog：素材の交換設定
- ptech_omnite_delivery_stores：店舗ごとのポイント・金庫
- ptech_omnite_delivery_runs：受注・確保金・支払い・返金履歴
- ptech_omnite_delivery_transfers：金庫の入出金履歴

テーブルは自動作成します。旧JOB共通ポイント表 ptech_omnite_delivery_accounts と旧market配置のDB行は削除しません。店舗ごとへの分配先が不明なので旧ポイントの自動複製は行わず、新店舗別残高は0から開始します。
新NPCのモデルは各配置に保存され、未指定の旧NPCは Config.npcModel を使います。
保存したプレイヤー中心座標へ、生成後にSetEntityCoordsNoOffsetで直接配置します。モデルの高さは減算しません。屋内や屋上の床を別の地面へ吸着させません。既存NPCにも生成時に補正を適用するため、更新後は `ptech_omnite_delivery` を再起動してください。
一般の現金販売NPCは工具箱の「ショップ管理」から設置してください。

## ゲーム内の配達演出

受注後にNPCが現れなくなる不具合は、クライアントで使用できない `os.time()` によりNPC生成ループが停止していたことをログで確認し、`GetCloudTimeAsInt()` へ変更しています。行き先案内・運搬表示・期限判定にも同じ修正を適用しています。更新後に本リソースを再起動してください。

近くの配達先・店舗NPCが消失した場合は自動再生成します。生成中のエラーも再試行し、地点名・ID・モデル・座標と原因をF8の `[Omnite delivery] NPC spawn failed` に記録します。NPCはミッションエンティティとして保持しますが、他リソースが明示的に削除する場合まで防ぐものではありません。

Config.gameplay で受け渡し時間・進行ガイド・運搬箱モデルを設定できます。既存の受け渡し・箱運搬・経路案内を維持しています。

## 起動・確認

`install/items.lua` の配達箱と素材5種類（普通・高級・甘味・タバコの葉・紅茶の茶葉）を `ox_inventory/data/items.lua` の `return { ... }` 内へ登録してください。既存IDは重複追加しません。

ox_lib / ox_target / ox_inventory / oxmysql / qbx_core の後に ensure ptech_omnite_delivery を指定します。
初めに店長が店舗金庫へ入金してから配達を受注してください。
テストは node dev/run.cjs（luaparse / fengariが必要）。受け渡し演出は node dev/gameplay.cjs で確認します。
FiveM実機・実DBでは未確認です。受注・複数人・納品・JOB変更・切断・期限切れ・再起動を確認してください。

NPCごとのモデルもConfig書き出しに含まれます。配達先NPCには店舗用のJOB・報酬設定を混ぜずに保存します。期限切れの返金処理と店舗操作は同時実行を防ぎ、一時的なDBエラーの後も次の定期確認で再試行します。報酬支払い済みでDB確定だけが失敗した場合も、再試行で報酬を重ねて支払いません。

仕様との対応、変更ファイル、試験結果と実機確認項目は [DEVELOPMENT.md](DEVELOPMENT.md) にまとめています。

大人の飲食物資は廃止済みです。更新後の起動時に、DB保存済みの交換リストからも該当アイテムだけを除外します。他の商品・交換率・店舗残高は保持します。既存インベントリを壊さないため、ox_inventoryに登録済みの旧アイテム定義と所持品は自動削除しません。
