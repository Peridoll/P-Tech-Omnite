# P-Tech Omnite Toolbox 0.6.0-dev

工具箱から椅子・ベッドの利用位置、2地点間のテレポーター、サークル、一般ショップ、ATM、依頼ボード、マップブリップ、宝箱NPC、ジョブ共有スタッシュを管理します。管理者向けに乗車中の車両複製も利用できます。椅子・ベッドの家具そのものは生成・移動しません。ATMはpropを生成します。

## ジョブ共有スタッシュ

管理者が工具箱→「ジョブ共有スタッシュ管理」→「現在地にジョブ共有スタッシュを設置」から配置します。スタッシュ名・共有するJOB・最低階級・スロット数・重量上限（kg）・有効状態を指定できます。初期容量は100枠・500kgです。配置・設定変更には管理者権限と工具箱が必要です。

利用者は設置地点のox_targetから開きます。同じ設置地点のスタッシュIDを、指定JOBのメンバーで共有します。最低階級0なら全階級が利用可能で、出勤状態は条件に含めません。利用するキャラクターの現在のJOBを判定します。利用者に工具箱は不要です。別の設置地点を作ると、それぞれ独立した中身になります。

一覧からJOB・階級・容量・名前・位置を編集できます。既存の配置を編集してもIDを維持し、中身を引き継ぎます。現在の重量を下回る重量上限への変更や、使用中のスロットが範囲外になる縮小は拒否します。削除は空のスタッシュだけ可能です。

サーバー側でもJOB・階級・距離・インスタンス・有効状態を確認し、直接IDを指定した開き方と、開いた後の出し入れにも条件を適用します。設定変更時は閲覧中の画面を閉じます。ジョブ変更で資格を失った場合は出し入れを拒否し、対象スタッシュを開いているかサーバーで確認して閉じます。

配置は`ptech_omnite_job_stashes`へ保存し、中身はox_inventoryが永続化します。DBユーザーにCREATE権限があれば配置テーブルは自動作成します。上限・初期容量・利用距離は`Config.JobStashes`で変更できます。新規の`main/client/job_stashes.lua`・`main/server/job_stashes.lua`と更新済みConfig・manifestを含めて反映し、`refresh`→`restart ptech_omnite_toolbox`で読み込んでください。

## 宝箱NPC

各キャラクターが、各NPCから一度だけ報酬セットを受け取れるNPCです。受取済みの記録はDBに保存し、再起動後も保持します。

1. 管理者が工具箱→「宝箱NPC管理」→「現在地に宝箱NPCを設置」を選び、名前・NPCモデルを指定します。新規は受取停止の状態で作成できます。
2. NPCを設置した位置の近くで、管理一覧の「報酬スタッシュを開く」を選びます。
3. 1人に渡したいアイテムと数量をスタッシュへ入れます。スタッシュの中身が報酬セットの見本で、配布しても見本は減りません。現金を配りたい場合は`money`アイテムを指定します。
4. NPCの設定で「報酬受取を有効にする」をオンにします。利用者はox_targetの「報酬を受け取る」から受け取れます。

管理操作にはadmin権限と工具箱が必要です。設定スタッシュはNPCの近くにいる管理者だけが開け、開いた後の移動操作にも同じ権限・距離・インスタンス条件を適用します。一般利用者に工具箱は不要です。

キャラクター識別にはQboxのcitizenidを使います。NPCの名前・位置・報酬を編集しても受取済みの記録は消しません。複数アイテム・数量・通常のメタデータを引き継ぎますが、武器シリアル・登録名・コンテナIDは受取先で新規発行させます。

空の報酬スタッシュや持ち物の空き・重量不足では、受取済みになりません。途中で渡せなかった場合は、同じNPCに話しかけると残りから再開します。一度受取を開始したセットは保存され、その後に管理者がスタッシュを編集しても途中のセットは変わりません。

アイテムを渡す処理とDBは単一トランザクションにできません。配布結果が未確定になった品目は自動で再配布せず、管理者が「未確定の受取を確認」で所持品・ログを照合し、その品目を渡し済み／未配布として確定できます。

NPCの削除前に報酬スタッシュの中身を取り出してください。未完了の受取記録があるNPCは削除できません。削除後も受取履歴は保持します。

設定は`Config.Treasure`、配置テーブルは`ptech_omnite_treasures`、受取記録は`ptech_omnite_treasure_claims`です。DBユーザーにCREATE権限があればテーブルは自動作成されます。新規の`main/client/treasure.lua`・`main/server/treasure.lua`と更新済みConfig・manifestを含むリソース全体を反映し、`refresh`→`restart ptech_omnite_toolbox`で読み込みます。

## ショップNPCの維持

ショップの80m以内へ近づくと一覧を再取得します。初回の一覧配信を取りこぼした場合も15秒ごとに再同期し、取得失敗時は5秒後に再試行します。インスタンスの切り替わりもサーバーが2秒ごとに確認して再配信します。自動再取得は失敗通知を連続表示しません。

NPCのモデル読み込みはショップごとに行い、一つのモデルを待つ間も他のショップの生成・復旧を継続します。同じ設定の再取得では正常なNPCを作り直さず、消失・死亡時の再生成と、非表示状態の解除を行います。距離・同期間隔・モデルの待ち時間は`Config.ShopStreaming`で調整できます。旧Configでこの設定が省略されている場合も既定値で動作します。

NPC生成後は保存位置と向きへ明示的に合わせて固定し、後からずれた場合も監視処理で元へ戻します。位置を変えない設定編集では配置を維持します。新規設置・移設はプレイヤーの現在の原点座標を使用し、旧形式の保存値は互換補正して読み込みます。補正を繰り返してDBの高さを書き換えることはありません。

ショップNPCはスクリプトの管理対象として生成し、無敵・ダメージ無効・ラグドール無効・位置固定を適用します。近くにいる間は通常約1秒ごとに存在と死亡状態を確認し、消失・死亡時は購入／補充／金庫のターゲットとともに再生成します。モデル読み込み・生成・ターゲット設定で例外が出ても、監視処理を継続して再試行します。

遠方では従来どおりNPCを片付け、近づくと再生成します。ログアウト・ショップ削除・リソース停止では片付けます。他リソースによる強制削除を禁止する機能ではありませんが、削除されたまま復元されない状態を防ぎます。

## 管理者の車両複製

車に乗った状態で、工具箱→「乗車中の車を複製」を選びます。管理者権限（`omnite.seating.admin`、`admin`、`god`のいずれか）と工具箱所持をサーバー側でも確認します。

ox_libの車両プロパティで改造・塗装・ホイール・ネオンなどを取得して複製先へ反映し、改造キット・全50スロット・トグル改造・通常／ルーフリバリー・エクストラ0〜20も補完します。元車の後方・左右・前方から、車両が近くにない出現候補を探します。候補がない場合は、広い場所へ移動して操作してください。

複製車には`OC`から始まる別ナンバーを付けます。個人車・ガレージ・所有権のDB登録は行いません。`qbx_vehiclekeys`が起動していれば、複製を実行した管理者へ鍵を渡します。外部リソース固有のエンジンスワップ、車両ごとのhandling上書き、独自statebag、トランクの中身などはコピー対象に含みません。

改造反映失敗・制御取得失敗・未完了のままの切断／タイムアウトでは、生成途中の複製車をサーバーで削除します。`Config.VehicleClone`で出現間隔・最大距離・連続実行の待ち時間・処理タイムアウトを設定できます。

新規の`main/client/vehicle_clone.lua`・`main/server/vehicle_clone.lua`を含めたリソース全体を反映し、`refresh`→`restart ptech_omnite_toolbox`で読み込みます。FiveM実機は未検証です。

## マップブリップ管理

工具箱→「マップブリップ管理」→「現在地にブリップを設置」で、地図のアイコンを配置します。管理者権限（`omnite.seating.admin`、`admin`、`god`のいずれか）と工具箱が必要です。表示を受けるプレイヤーは工具箱不要です。

- 名前・アイコンID（Sprite）・色ID（Colour）・大きさを指定します。
- 通常は全体マップだけに表示します。「ミニマップにも常時表示する」にチェックを入れたブリップだけ、距離に関係なくミニマップにも表示します。既存データの未設定はチェックなしとして扱います。「有効化」で表示自体を切り替えられます。
- 一覧から設定を編集、現在地へ移動、確認後に削除できます。位置を移動しない場合は「現在地へ設置・移動する」のチェックを外します。
- 同じインスタンス内のプレイヤーへ表示設定を反映します。インスタンス変更、ログアウト、リソース停止で不要なアイコンを取り除きます。
- 配置は`ptech_omnite_map_blips`テーブルに自動保存し、再起動後に復元します。DBに保存できなかった変更は反映しません。
- 「Config形式でコピー」は現在のインスタンスの配置を`Config.MapBlips.fixed`形式で出力します。同じIDのDB保存を優先し、削除済みIDはConfigに残っていても復活しません。

新規設置の初期値・上限は`Config.MapBlips`で変更できます。アイコンID・色IDは[Cfx公式ブリップ一覧](https://docs.fivem.net/docs/game-references/blips/)に合わせて指定してください。入力範囲内でもゲームに存在しないアイコンIDの描画は保証できません。

サーバーへ反映する際は、新規の`main/client/map_blips.lua`・`main/server/map_blips.lua`と更新済みConfig・manifestを含め、リソース全体を反映してください。その後、サーバーコンソールで`refresh`、`restart ptech_omnite_toolbox`を順に実行します。

## サークルの種類

工具箱→「サークルエリア管理」から「スターターサークルを設置」「人除けサークルを設置」を選べます。管理者のみ設置・編集・削除できます。

| 種類 | 動作 |
|---|---|
| スターターサークル | 有効な範囲を常時表示。一度入った人が出ると警告後に連れ戻す。初期キャラ設定・顔コード・パスワード脱出 |
| 人除けサークル | 設定中だけ範囲表示。自然発生NPCを生成前にキャンセル。プレイヤーは出入り自由 |

人除けは名前・半径・中心・有効／無効を設定し、保存すると即時反映します。既存と同じXYの円形範囲で、高さによる制限はありません。同じインスタンス内の範囲だけを適用し、出現処理を各クライアントで抑止します。既に存在するNPCや範囲外から歩いて入るNPCの削除、ショップなどがスクリプトで生成するNPCの削除は行いません。

両方とも同じDBテーブルで保存・再起動復元します。旧データは自動的にスターターとして扱い、設置名・中心・設定を維持します。人除けには連れ戻し・キャラ設定・脱出機能を適用しません。人除けの地図範囲・中心マーカー・ターゲットは通常表示せず、工具箱の一覧から設定を開いたときに範囲プレビューを表示します。

## ATM・依頼ボードの操作

管理者の工具箱に「ATM管理」「依頼ボード管理」を追加しています。椅子・ベッド以外の管理には管理者権限が必要です。依頼ボードは`ptech_omnite_requests`の起動が必要です。

ATMは「現在地にATMを設置」から名前・モデル・高さを指定します。既存の銀行リソースが反応する標準ATMのpropを配置する機能で、独自の入出金処理は持ちません。編集は設置地点の近くで行い、削除には確認画面を表示します。`Config.ATMs`で利用モデル・上限・描画距離を指定します。配置は`ptech_omnite_atms`へ自動保存し、再起動後に復元します。管理画面から現在のインスタンスの配置を`Config.ATMs.fixed`形式で出力できます。同じIDのDB配置を優先し、削除済みIDはConfigに残っていても復活しません。

ATMのpropは近くのクライアントで生成し、遠ざかる・インスタンスが変わる・リソースが停止する際に除去します。銀行側が選択モデルを受け付けるか、実機で確認してください。依頼ボードの設置・権限については`ptech_omnite_requests/README.md`を参照してください。

## 導入

1. OneSyncを有効にし、`ox_lib`、`ox_target`、`oxmysql`、`ox_inventory`、`qbx_core`を先に起動します。
2. リソース直下の`install/items.lua`の項目を`ox_inventory/data/items.lua`のreturnテーブルへ追加します。ファイル自体を置き換えないでください。
3. `server.cfg`に`ensure ptech_omnite_toolbox`を追加します。DBユーザーにはCREATE権限が必要です。椅子用の既存テーブル`ptech_omnite_seating`・`ptech_omnite_seating_mlos`はそのまま使用し、テレポーター用に`ptech_omnite_teleporters`を作成します。
4. 管理者に`add_ace group.admin omnite.seating.admin allow`を設定します。
5. 管理者またはサーバーコンソールから`omnite_seatgive <プレイヤーID>`でツールを1個配布します。ショップ・クラフト・通常ドロップには登録しません。

アイテムは消費せず、登録・編集・削除時にサーバーで所持を再確認します。他の管理リソースからアイテムを生成できる権限は、その管理リソース側で管理してください。

### Seatingからの移行

旧`ptech_omnite_seating`を停止し、フォルダと起動設定を`ptech_omnite_toolbox`へ変更します。両方を同時に起動しないでください。登録済み`pomnite_toolbox`の`client.export`と`server.export`を両方とも`ptech_omnite_toolbox.usePlacementTool`に変更し、アイテム設定を読み直します。アイテム名・画像URL・既存の席データ・座席関連のイベント名・ACE・従来コマンドは維持します。外部リソースからのexports呼び出し先も新しいリソース名に変更します。Mediora Escortの`PreparePatientBed`は新旧の呼び出し元を受け付けます。

## テレポーターの設置・利用

工具箱の「テレポーターの管理」→「新しいテレポーターを設置」で登録画面を開きます。

1. 名前を入力し、通行方向を「A→B」「B→A」「A↔B」から選びます。
2. 「地点Aを指定」を選び、設置したい場所に歩いて移動してEを押します。現在地と向きをサーバーで記録します。
3. 同じ手順で「地点Bを指定」します。2地点は1m以上離し、同じインスタンス内で指定します。
4. 「保存して設置」でDBへ保存します。保存前にキャンセルすると設置しません。

入口に近づくとマーカーとEの案内を表示します。複数の入口が重なる場合は一覧から選択します。一方通行の出口側には利用案内を出しません。利用する人は工具箱不要です。車内・着席中・死亡中・拘束中・搬送中には利用できません。移動先を読み込めなかった場合は元の場所へ戻し、移動操作を解除します。地点を指定する際は、歩いて立てる床の上で記録してください。

管理一覧から既存のテレポーターを選ぶと、名前・通行方向・2地点を編集、または確認後に削除できます。工具箱所持者は他の人が登録したものも編集・削除できます。再起動後も登録を復元します。

## 配置と利用

インベントリの「Omini工具箱」（`pomnite_toolbox`）を「使う」→「椅子やベッドの管理」で管理モードに入ります。近く30m以内の登録済み地点をマーカー表示し、画面に使い方を表示します。マーカーは管理モード中だけ表示します。Escで管理モードを終了します。補助コマンド`/omnite_seating`も、工具箱を所持した状態で利用できます。

### 新規登録

配置したい場所へ移動し、Eを押すと「登録情報」が開きます。プレイヤーの現在地と向きが調整の開始地点です。

1. **MLOを登録**：新しいMLO名を入力してDBへ保存します。日本語の名前も使用でき、まだ席がないMLO名も再起動後に残ります。
2. **MLOを選択**：登録済みのMLO名から選択します。従来の席に付いているMLO名も選択できます。
3. **座席名を指定**：任意の名前を指定できます。日本語対応、空欄はランダム名です。
4. **種類を指定**：イス・カウンター・ベッドを選びます。Mediora起動中の医療職だけに病院ベッドを表示します。
5. **作成**：スライダーの調整画面へ進み、位置・姿勢を確認して「保存する」で確定します。

### 既存地点の編集・削除

マーカーの近く（1.75m以内）でEを押すと「編集」「削除」を表示します。範囲内に複数のポイントがある場合は、先に操作対象の一覧を表示し、名前・MLO・種類・距離・IDを確認して選択できます。1地点だけなら直接編集メニューを開きます。選択後も地点の存在と距離を確認します。編集はスライダー画面、削除は確認後にDBから削除します。編集を保存・キャンセルした後は管理モードへ戻ります。近くに既存席があっても別の席を増やしたい場合はShift+Eで新規登録できます。

工具箱を持っていれば、登録者以外でも登録済みの席を編集・削除できます（`Config.Placement.editByToolHolder = true`、`Config.Placement.deleteByToolHolder = true`）。登録者の情報は編集後も保持します。削除は確認画面で確定し、使用中の席は削除できません。同じ家具への地点追加は従来どおり登録者または管理者だけが実行できます。病院ベッドは編集・削除にも医療職の条件を適用します。Configに直接書いた固定席はマーカーを表示しますが、変更は設定ファイルから行います。

### コピーして新規作成

既存地点の編集メニューで「コピーして新規作成」を選ぶと、MLO・種類・位置・向き・初期姿勢を引き継いで調整画面を開きます。自動生成された名前（`seat_数字6桁_数字`）は新しく振り直し、手入力した名前は引き継ぎます。位置を調整して保存するとDBで新しいIDを発行します。キャンセルした場合は作成しません。コピー元は変更せず、作成者が所有する独立した家具グループとして保存します。同じ家具グループへ増やす場合は「同じ家具に利用地点を追加」を使ってください。病院ベッドのコピーにも医療職の条件を適用します。

### ベンチ・ソファ・複数ベッドのグループ

最初の利用地点を登録し、そのマーカーでE→「同じ家具に利用地点を追加」を選びます。MLOは引き継ぎ、追加する地点の名前・種類を指定してスライダーで別の位置へ調整します。ベンチに3つの座る地点、ソファに座る地点と寝る地点、同じ家具周辺に複数の寝る地点などをまとめて管理できます。

各地点は別のターゲット・初期姿勢・占有状態を持ちます。「同じ家具の利用地点」で一覧表示し、個別に編集・削除できます。1グループは既定で32地点まで、同じMLO・インスタンス内で最初の地点から15m以内です。グループへの追加権限も所有者・管理者をサーバーで確認します。

家具グループは利用地点を整理するための情報です。家具オブジェクト自体を生成・移動せず、家具が移動しても固定座標の利用地点は自動追従しません。

すでにアイテムを登録済みの場合は、`client.export`・`server.export`を両方とも`ptech_omnite_toolbox.usePlacementTool`に変更してください。画像URLはそのまま使用できます。

半透明の自分の姿勢を見ながら、画面右側のスライダーで調整します。

調整中は赤X（左右）・緑Y（前後）・青Z（高さ）の矢印と、向きの回転を示す水平リングを表示します。左右・前後の移動は現在の向きに沿います。向きだけを変えても位置は動かず、次の移動操作から新しい軸方向を使います。高さは垂直方向です。軸とリングは目印で、操作はスライダーまたは数値入力で行います。左右・前後の数値は移動操作の累計で、回転後は開始地点に対する固定座標を表しません。

各スライダーの数値欄へ直接入力することもできます。左右・前後・高さはm、向きは度、座り方は候補の番号です。Enterまたは入力欄から離れると確定し、範囲外の値は上下限へ補正します。空欄・不正な値は直前の有効値へ戻します。地面ボタンで変わった高さの下限も数値欄へ反映します。

| 操作 | パネル |
| --- | --- |
| 左右・前後・高さ | 各スライダー（開始地点から±2m、1cm刻み） |
| 向き | 向きスライダー（0〜359.9度） |
| 初期姿勢 | 座り方スライダー。種類に対応する候補を表示 |
| 歩いて確認 | 「歩いて位置を確認」または左ALT。移動キーで歩き、左ALTでスライダーに戻る |
| 地面に合わせる | 「地面に足をつける」でプレビューの足を地面に合わせ、その高さを下限に設定 |
| DBへ確定保存 | 「保存する」 |
| 中止 | 「キャンセル」またはEsc |

左右・前後の基準は調整開始時の向きです。向きを回転させても位置スライダーの軸は変わりません。ベッドには横になる姿勢を表示します。保存中は操作を止め、失敗時は調整を維持して再試行できます。ALTで歩いて離れても編集を破棄しませんが、保存時は登録地点から8m以内に戻る必要があります。

地面ボタンは、プレイヤーがいる階の足元付近から利用地点の下方向へ床を調べ、プレビューの足の高さを合わせます。床が取得できない場合は高さを維持して通知します。MLO・特殊な家具・アニメーションごとの見え方は実機で確認してください。

DB保存成功後に接続中プレイヤーへ反映し、再起動後も復元します。失敗時は有効化せず、調整画面を維持します。登録地点はプレイヤーから8m以内です。

登録済みのイス・カウンターはox_targetから座り、ベッドは「横になる」で利用します。Xで解除、Gで本人用の姿勢メニューを開きます。工具箱は不要です。本人の姿勢変更では配置位置やDBの初期姿勢は変更しません。

イス・カウンターでXを押すと、周囲の前後左右0.85・1.25・1.75mの候補を調べ、床と立てる空間が確認できた地点へ直接移動して操作を戻します。立ち上がりアニメーションと自動歩行は行いません。候補がなければ着席前の地点も検証し、どこにも立てない場合は座った状態を維持して通知します。MLOの床・家具の衝突形状による見え方は実機確認が必要です。

0.4.7では探索処理をクライアント本体へ統合し、別ファイルの読み込みに依存しないようにしています。探索中に例外が出た場合も、動作・固定・席の占有を解除してエラー内容を記録します。

場所の探索中は二重着席を防止します。探索の例外でも終了処理を完了し、死亡・車両への移動・リソース停止では探索を待たず解除します。ベッド・患者の状態管理は従来どおりです。着席時の操作案内は表示しません。

固定・衝突状態も着席前の値へ復元します。移動不能が再発した場合は`/omnite_seatdiag`を実行し、F8の`[Seating 0.4.3]`の行を確認してください。席の内部状態・固定・衝突・シナリオ・NUIフォーカス・移動入力を読み取り表示します。

| 席の種類 | Gメニューの現在の全候補 |
| --- | --- |
| イス | 標準・背筋を伸ばす＋下記のSit Chair 7種類 |
| カウンター | カウンター座り・標準・背筋を伸ばす＋下記のSit Chair 7種類 |
| ベッド | 仰向け・睡眠・うつ伏せ・リラックスして横になる |
| 病院ベッド | 仰向け・睡眠・うつ伏せ・リラックスして横になる |

追加した座り方はSit Chair、Sit Chair 2、Sit Chair 4 - Side、Sit Chair Legs Crossed、Sit Chair Lean Back、Sit Chair Attentive、Sit Chair Lonelyです。Female表記の候補とArmchairは含めません。従来のArmchair系「ゆったり」は選択肢から外し、保存済みの`armchair`は標準姿勢として読み込みます。

通常ベッドでも利用中の位置固定とラグドール防止を適用し、寝姿が中断された場合は500ms間隔で確認して再生を戻します。アニメーション切り替え時は前の動作を即時解除して競合を避け、Xで離れると着席前の固定・ラグドール状態を復元します。

姿勢の追加・種類ごとの割り当ては`Config.Seating.styles`と`Config.Seating.kindStyles`で共通管理します。Configの各席やモデルで`styles`を指定した場合は、その制限も適用します。新しいConfig出力は初期姿勢を`style`として出力し、Gの候補を1種類へ制限しません。ゲーム標準のアニメーションを直接使うためrpemotes-rebornの起動は不要です。ポーズ固有の位置・向き補正は各スタイルの`offset`・`headingOffset`で調整できます。MLO家具との位置合わせは実機確認が必要です。

1地点1人で、同じ位置を別IDで登録しても重なって利用できません。移動・攻撃を制限し、スマホ・インベントリ用の入力は開放しますが、各リソースとの併用は実機確認が必要です。

管理モードのマーカーから近くの自分の席を編集・削除できます。管理者は他の所有者の席も操作できます。患者用ベッドの編集・削除にもEMS条件を適用します。使用中の席は変更できません。

## ベッドとMediora

- 椅子・通常ベッドの登録はツール所持者が利用できます。
- 患者用ベッドの登録は、ツールを持ち、`ptech_mediora_medical`が起動しているEMSだけが利用できます。
- JOB名は`Config.Placement.emsJobs`で指定します。グレード・出勤状態は条件に含めません。
- EMSは患者用ベッドのターゲットから、近くの患者IDを選んで移動を要求できます。EMS・患者・ベッドの距離、同一インスタンス、空席状態をサーバーで確認します。
- 死亡・ラグドール・拘束など、通常の着席を開始できない状態は移動を断り、占有を解除します。蘇生やMediora/Wasabiの死亡状態は変更しません。意識不明患者への適用は、それらの状態管理と連携する追加調整・実機確認が必要です。

Medioraサーバーコードから利用できる連携口もあります。

```lua
local beds = exports.ptech_omnite_toolbox:GetPatientBeds()
local result = exports.ptech_omnite_toolbox:PlacePatientInBed(emsSource, patientSource, bedId)
-- result.ok / result.message
```

`PlacePatientInBed`は`Config.Placement.medicalResource`からの呼び出しだけを受け付けます。ベッド一覧が変わったら従来と同じサーバーのローカルイベント`ptech_omnite_seating:server:patientBedsChanged`を通知します。

## MLO単位のConfig出力

管理者メニューからMLO管理名を指定してConfig形式をクリップボードへ出力できます。空欄は全件です。DBの内容を自動削除したり、設定ファイルを自動上書きしたりはしません。

出力は`Config.FixedSeats`用です。既存設定がある場合は必要な行を追加してください。移行時はDBをバックアップしたうえで対象DB席を整理し、同じ席をDBとConfigへ二重登録しないでください。Configはリソース再起動時に読み込みます。

## 管理用の従来コマンド

`/omnite_seatdebug`は近くの登録席を表示し、`/omnite_seatghost`は近くのオブジェクトを貫通します。どちらもサーバーACE制限付きです。新配置モード中は選択対象だけを一時的に貫通します。全オブジェクトの走査は管理用デバッグ・貫通モード中だけ動作します。

```cfg
add_ace group.admin command.omnite_seatdebug allow
add_ace group.admin command.omnite_seatghost allow
```

旧`omnite_seatrecord`・`omnite_seatsetup`は`Config.SeatRecorder.enabled`がtrueの場合だけ有効で、それぞれの`command.<名前>` ACEが必要です。DB保存を使う場合は新ツールを使ってください。

## 検証

リソース直下（`package.json`のある場所）で`npm install --ignore-scripts`後、`npm test`で`dev/tests/run.cjs`を実行し、Lua構文と、疑似サーバー上のDB失敗・所有権・EMS・距離・座席競合・再起動復元を確認できます。検証用依存ライブラリはFiveM実行時には不要です。

今回の自動確認は通過しています。実MySQL・FiveM・MLO上の位置、NUI、ベッド姿勢、他のアニメーションとの干渉は未検証です。ゲーム内で配置→2人同時着席→編集→再起動→復元→Config出力の順に確認してください。

## ダウン患者のベッド搬送（Mediora Escort連携）

病院ベッド（`patient_bed`）の「患者をベッドへ移す」をEMSが選択します。自分が担いでいる患者が近くにいる場合はその患者を自動選択し、それ以外は近くの患者を選びます。患者・EMS・ベッドは同じインスタンス内で3m以内にいる必要があります。

Mediora Escort起動中は勤務中のEMSが操作し、現在の搬送者以外による横取りは拒否します。ベッド確保後にサーバー専用の`PreparePatientBed`で搬送を解除し、失敗した場合はベッド確保も取り消します。SeatingとEscortの両方を更新してください。

ダウン中もベッドの姿勢を維持し、体力・傷・死亡フラグは変更しません。EMSは通常のMedicalカルテから診察・治療・蘇生します。蘇生後は患者自身がXで降りられます。ダウン中のX・姿勢変更は無効です。リソース停止や強制解除では固定とラグドール設定を復元します。Wasabi側のファイル変更はありません。

自動テストは死亡中の着床、蘇生後の退出、強制解除、搬送権限と搬送解除失敗時のベッド解放を確認します。実機ではMLOのベッド位置とWasabiの死亡・蘇生アニメーションとの干渉を確認してください。
