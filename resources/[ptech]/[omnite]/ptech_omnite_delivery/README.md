# Omnite Delivery

店舗の店員が箱を集荷・納品し、個人の現金報酬と店舗共通の箱ポイントを獲得します。箱ポイントは店員全員が素材交換に使用できます。スーパーでは、登録店舗のボスだけが個人の現金で素材を購入できます。素材は購入者のインベントリに入り、各自で店舗の飲食スタッシュへ移します。

アイテムは配達用の箱・普通・高級・甘味・紅茶の茶葉・タバコの葉の6種類です。箱と飲食物資の `client.image` は、このリポジトリの `feature/dev` に置いた画像の直接URLを指定しています。紅茶の茶葉・タバコの葉の個別画像は未設定です。

## 導入

1. `install/items.lua` の定義を `ox_inventory/data/items.lua` の `return { ... }` 内に追加します。既存素材を利用する場合は、`config.lua` の `products[].item` を既存IDに変更してください。その場合、対応するサンプル素材定義は追加不要です。配達用の箱は必須です。
2. `oxmysql`、`ox_lib`、`ox_target`、`ox_inventory`、`qbx_core` を起動した後に `ensure ptech_omnite_delivery` を追加します。
3. ツールボックスも今回の `main/client/placement.lua` へ更新し、再起動します。
4. 管理者が工具箱を持ち、ツールボックスの「配達・素材仕入れの管理」を開きます。
5. 店舗NPC（ジョブ名を指定）、集荷NPC、スーパーNPCを登録します。同じルーティングバケットに集荷NPCが1体以上必要です。

DBのテーブルはリソース起動時に自動作成します。作成権限がない場合はサーバーログに初期化エラーが出て、配達・購入を停止します。

管理には `omnite.delivery.admin`、`admin`、`god` のいずれかのACEと `pomnite_toolbox` が必要です。入口のツールボックス側でも管理者判定を行います。独自ACEを使う場合は両リソースで管理者設定を揃えてください。

## ゲーム内の流れ

- 店舗NPCをターゲットし「配達を受注」。その店舗のジョブに現在所属しているプレイヤーだけが受注できます。
- 登録済み集荷地点からランダムに1か所を指定し、箱のブリップとルートを表示します。
- 指定された集荷NPCをターゲットして箱を受け取ると、ルートが元の店舗へ切り替わります。
- 元の店舗NPCへ箱を納品すると、受注者に現金、店舗のジョブ共通口座に箱ポイントを加算します。
- 店員は店舗NPCで残高を確認し、ポイントで素材を購入できます。購入数量と合計を確認してから交換します。
- 登録店舗のボスはスーパーNPCで現金購入できます。店舗の口座からの支払いではありません。

出勤は初期設定では不要です。`requireDuty = true` にすると、配達・素材購入とも出勤が必要になります。

## 初期値と調整

未決定の値は試運転用の仮設定です。

| 項目 | 初期値 | 変更箇所 |
|---|---:|---|
| 個人の配達報酬 | 10,000 | 店舗NPCの設定 |
| 納品時の店舗ポイント | 1 | 店舗NPCの設定 |
| 普通の必要ポイント | 1 / 個 | `products[].points` |
| 高級・甘味・紅茶の茶葉・タバコの葉の現金価格と必要ポイント | 未設定（購入不可） | `products[].cash` / `products[].points` |
| 普通の飲食物資の現金価格 | 7,500 | `products[].cash` |
| 配達の制限時間 | 30分 | `missionSeconds` |
| 受注間隔 | 60秒 | `cooldownSeconds` |

登録地点は即時反映し、再起動後も保持します。進行中の配達はサーバー側で管理し、受注者・ジョブ・集荷地点・納品先・距離・バケット・配達専用の箱を照合します。途中でジョブを変えると配達を取り消します。二重受注・二重集荷・二重納品を拒否します。

所持枠が足りなければ集荷・購入は成立しません。素材の受け渡しに失敗した場合は消費したポイントまたは現金を戻します。納品のDB更新に失敗した場合は箱を返し、再試行できるようにします。

## 保存・書き出し

- 配置：`ptech_omnite_delivery_locations`
- 店舗ポイント：`ptech_omnite_delivery_accounts`（ジョブ単位）
- 「配置をConfig形式で書き出す」で `Config.locations = { ... }` をコピーできます。
- 同じIDがDBとConfigにある場合、DBの配置を優先します。Configへ完全移行する際は書き出し内容を保存後、リソースを停止して対応するDB配置行を削除してください。ポイント口座は削除しないでください。
- Config登録地点をゲーム内で編集するとDBに上書き設定を保存します。Config登録地点そのものの削除は設定ファイルから行ってください。

配達の進行状態はメモリ管理です。切断・制限時間・リソース再起動で終了します。期限切れやジョブ変更時には所持中の配達箱を回収します。切断時や再起動時に残った箱、他人に渡した箱は次の配達で使えません。配置と店舗ポイントは残ります。サーバー強制終了の瞬間を含む、インベントリ・現金・DB全体の原子的な保存は保証しません。

受注・購入・納品は徒歩距離をサーバーでも確認します。既存の料理リソースのレシピやスタッシュ定義はこのリソースから変更しません。初期素材IDを使う場合、料理側のレシピでも対応する素材IDを指定してください。

## 開発確認

リポジトリに既存の `.omnite-checks/node_modules` がある環境では、ルートから実行できます。

```powershell
node 'resources/[ptech]/[omnite]/ptech_omnite_delivery/dev/run.cjs'
```

Lua構文、所属・距離・バケット制限、二重納品、所持枠不足、DB失敗、報酬失敗時の補償、共有ポイント、ボス限定購入をモックで検証します。NPC表示・ターゲット・ブリップ・実際のQbox/ox連携はFiveM実機での確認が必要です。
